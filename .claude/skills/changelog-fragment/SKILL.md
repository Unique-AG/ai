# Changelog fragment (platform release notes)

Package `CHANGELOG.md` files in this repo are developer-facing and generated by release-please from commit subjects — never edit them (see `release-process`). They do **not** reach customers.

Customer-facing release notes are assembled in **Unique-AG/monorepo** from Changie fragments (`.changelog/unreleased/*.yaml`, config `.changie.yaml`). Every PR here that changes user-visible behaviour of a published package must add such a fragment; the monorepo's `Release · Sync AI Versions` workflow copies the fragments added since the previously pinned AI commit into its own `.changelog/unreleased/` when it bumps the `unique-*` pins, and `changie batch` folds them into `.changelog/<version>.md` for the release. Without a fragment the change never appears in the release notes.

`.changie.yaml` here is a copy of the monorepo's and must stay identical (same kinds, components, custom fields) so fragments can be copied verbatim.

## Create a fragment

Non-interactive (the only mode; no TTY prompts):

```bash
uv run poe changelog-new \
  --kind Fixed \
  --component "API / SDK" \
  --body "Short, client-facing description of the fix." \
  --custom Audience=user \
  --custom Ticket=UN-12345
```

- `--kind` — one of `Added`, `Changed`, `Fixed`, `Removed`, `Security`.
- `--component` — one of `Administration / Governance`, `API / SDK`, `Chat Experience`, `Conduct`, `Connectors`, `Infrastructure`, `MCP`, `Pod AT`, `Pod KYC`, `Pod RM`, `RAG`, `Web Search`. Pick the platform area the *user* experiences, not the package: `unique_toolkit`/`unique_sdk` changes are usually `API / SDK` unless they change an agent (`Conduct`), search (`RAG`, `Web Search`), a connector (`Connectors`) or MCP behaviour.
- `--custom Audience=` — required, one of `user`, `admin`, `operator`.
- `--custom Ticket=` — optional; one or more `UN-<number>` keys, comma-separated (quote the value: `--custom "Ticket=UN-1, UN-2"`).
- `--dry-run` prints the YAML instead of writing it.

The script writes `.changelog/unreleased/<kind>-<component>-<timestamp>.yaml`. Commit it together with the code change; check the diff contains exactly `component`, `kind`, `body`, `time`, `custom.Audience` and optionally `custom.Ticket`.

Run `uv run poe changelog-check` locally to reproduce the CI job (diffs `HEAD` against the merge-base with `origin/main`; needs `yq` for fragment validation).

## Body wording

Write `--body` the way a release note reads: concise, present tense, client-facing, no internal nomenclature, no package names as the subject, no Jira keys (those go in `Ticket`; the script rejects `UN-…` inside the body). The rendered line is `- (<Audience>): <Body> (<Ticket>)` under `### <Component>` / `#### <Kind>` headings, so never restate the kind or component in the body.

For `Fixed`, mirror the existing style:

```
The problem with X happening under Y circumstances now works as intended.
```

For `Added`/`Changed`/`Removed`/`Security` describe the user-visible effect only.

State how the change is switched on: name any feature flag, env var, company config key, space setting or Helm value that gates it and whether it is on by default; say "API-only" when the UI has no control; if behaviour changes for users who did not opt in, prefix that part with `Behavior change:`. For a large feature, link a Confluence page instead of over-explaining inline.

## When a fragment is not needed

`.github/scripts/changelog-check.sh` (CI job `Changelog Fragment` in `ci.yaml`) skips PRs whose changed files all match its `EXCLUDED_GLOBS` (tests, docs, `tutorials/`, `.github/`, `.claude/`, lockfiles, release-please artifacts, helm charts) and PRs labelled `no-changelog`; release-please, `chore/bump-dev-*`, dependabot and renovate PRs are skipped entirely.

Apply `no-changelog` for pure refactors, internal tooling, dependency bumps and anything with no user-visible effect — do not write a fragment just to satisfy the check. The check reads labels from the PR event, so after adding the label re-run the `Changelog Fragment` job (or push a commit).

Rollout: the job is warn-only until the repository variable `CHANGELOG_CHECK_ENFORCE` is `true`.

## Examples

Fix with a ticket:

```yaml
component: API / SDK
kind: Fixed
body: The problem with streamed completions dropping the last token when the model closes the stream early now works as intended.
time: 2026-09-08T21:06:07.123456+02:00
custom:
    Audience: user
    Ticket: UN-24991
```

Flag-gated addition:

```yaml
component: Web Search
kind: Added
body: Web search results now include the publication date of each source. Disabled by default; enable via the `include_publication_date` tool setting in the space configuration.
time: 2026-09-08T21:06:07.123456+02:00
custom:
    Audience: admin
```
